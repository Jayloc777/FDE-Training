0. 课程定位与边界

0.1 入门班解决什么问题

入门班不是“提示词技巧班”，也不是把一堆 AI 工具逐个演示一遍。它要让零基础、非技术或技术基础薄弱的学员形成 FDE 的第一层工作习惯：

先看用户和任务，再定范围；先定义输入和输出，再选工具；先测试失败，再展示成功；先保留证据，再谈完成。

0.2 结课能力边界

通过入门班，学员应能在教师提供的脚手架、模板和脱敏材料中：

  1. 把宽泛的 AI 想法收敛为一个用户的一个工作任务；
  2. 画出 5-7 步的用户路径和一条失败路径；
  3. 写出结构化输入、输出、成功和失败条件；
  4. 整理有来源、有版本、有用途的材料包；
  5. 使用低代码、模板或教师提供的适配器完成一个可运行 Demo；
  6. 执行固定测试，记录失败并完成一次证据驱动的修订；
  7. 写出第三方可执行的运行说明；
  8. 用 3 分钟演示清楚区分已实现、未实现和必须人工处理的部分。

0.3 结课不代表什么

  • 不代表能够独立完成企业 AI 项目；
  • 不代表达到独立 L2、L3 或 L4；
  • 不代表可以接触客户生产系统或敏感数据；
  • 不代表可以自动执行退款、删数、发信、改价、授信、诊断等高风险动作；
  • 不代表就业或项目录用。

入门班的目标是形成 L1 Assisted Execution 证据，为进阶班学习做准备。

1. 课程结果

1.1 学员最终产出

每位学员提交个人证据包，每个小组提交一个 MVP-DEMO-01 项目包。

产出最低要求
场景机会卡一个用户、一个任务、一个可观察结果、至少两项范围外动作
Demo Brief用户、问题、输入、输出、正常路径、失败路径、范围和成功条件
输入输出契约字段、类型、必填、枚举、错误返回和示例
材料包脱敏材料、材料 ID、来源、版本、用途和限制
测试集T01-T12 共 12 条，覆盖正常、边界、异常和禁止行为
测试结果12 条实际运行记录，包含预期、实测、证据定位和版本
失败清单至少一个真实复现或教师注入的失败，含 owner 和状态
修订记录至少一次从失败/评审证据出发的修改和回归
Runbook未参与制作的同伴能在 10 分钟内启动和复现
3 分钟演示正常路径、失败路径、证据和边界都能说明

上述 10 项文件对应归档物料定义的 9 类证据：T01-T12 测试集与测试结果属于同一类证据，但建议拆成 05_TEST_CASES.csv 和 06_TEST_RESULTS.csv 两个文件，分别保存预期与实测。九类证据的完整顺序是：机会卡、Demo Brief、输入输出契约、材料包、测试集与结果、失败清单、修订记录、Runbook、3 分钟演示。

1.2 证据包的统一记录字段

  • 测试记录：test_id,input_or_fixture,expected_result,actual_result,evidence_ref,status,run_version,run_at。
  • 失败记录：failure_id,trigger,observed,expected,severity,evidence_ref,owner,status。
  • 修订记录：revision_id,from_version,to_version,trigger_evidence,change,affected_tests,result。
  • 截图必须同时有文字定位；截图不能替代可复制的输入、输出和运行记录。
  • PASS 必须绑定到具体 Demo 版本；任何修改都必须重跑受影响测试。

1.3 L1 能力表现

能力入门班通过表现
技术能力能在脚手架内完成配置、运行、基本排错和结构化输出
业务能力能说明用户、任务、当前做法和最小业务结果
产品能力能做范围削减，拒绝“万能助手”和“替代岗位”
交付能力能按版本、测试和 Runbook 交付，不只发截图

2. 受众、准入与班级配置

2.1 适合人群

  • 想从 AI 工具使用转向 AI 应用实践的人；
  • 业务、运营、产品、咨询、实施和销售支持人员；
  • 有行业经验但不懂代码和系统的人员；
  • 想进入 FDE 路径、需要先建立项目证据的人；
  • 技术基础薄弱但愿意按流程记录和练习的人。

2.2 不要求的能力

  • 不要求 Python；
  • 不要求数据库或云平台经验；
  • 不要求了解某个固定大模型品牌；
  • 不要求有企业客户资源；
  • 不要求第一次就能写复杂代码。

2.3 建议运行参数

  • 4 天、8 节；每天 2 节；
  • 每节名义时长 90 分钟，课堂总时长 12 小时；
  • 课前环境预检约 30 分钟；每节之间或当天课后安排 30-60 分钟证据任务；建议总学习投入约 18-20 小时；
  • 每组 3-5 人；
  • 每场 1 名主讲 + 2 名助教；
  • 首期正式学员上限 30 人。

课前预检、节间任务和课后证据任务属于课程闭环的一部分，不计入 90 分钟课堂时长。以上是课程运行设计值，首期要记录真实教学时长、求助峰值、首次运行成功率、节间任务按时率和补做率，不把设计值写成已经验证的最佳配置。

3. 教学设计原则

3.1 三种学习活动

每个教学日同时安排：

  1. 课前自主学习：阅读短材料、工具说明或信号库条目，并完成环境预检；
  2. 课堂专题分享与开放实践：用微课、示范、实训和同伴走查把 FDE 方法转成项目证据；
  3. 节间/课后开放实践：补齐材料、运行记录、失败复现和文档，让下一节从已有证据继续，而不是重新听讲。

3.2 每节 90 分钟结构

环节时间内容
进入门票与检索8 分钟回答上一节的关键判断，暴露未完成证据或错误假设
微课与案例12 分钟只讲本节完成任务必需的概念、边界和一个真实案例对照
教师示范15 分钟展示一个能跑但有缺陷的版本，明确输入、输出和失败点
分组实训37 分钟小组协作、角色轮换，直接修改模板或运行 Demo
同伴走查 / 测试12 分钟另一组按用户、证据和失败路径检查，至少留下一个反馈
证据关闭与出门票6 分钟保存版本、结果、失败和修改记录；每人写一个未验证项

90 分钟中至少 49 分钟用于示范之后的动手、走查或测试；任何安装、长篇工具比较和自由浏览都不占用这段核心课堂时间。

3.3 入门班的安全设计

  • 只使用公开材料、虚拟材料或已脱敏材料；
  • 使用教师提供的沙箱、模拟接口或回放数据；
  • 学员不得保存真实客户姓名、联系方式、账号、密钥和生产数据；
  • 系统只做建议、整理、检索和草稿；
  • 任何写回或对外发送动作都由教师模拟，并保留人工确认；
  • 课堂 Demo 不得直接连接生产系统。

3.4 四天压缩的保留项与迁移项

压缩版采用“课堂保关键判断，课外做可重复劳动”的原则。迁移时间不代表降低要求，而是把学员独立完成、教师可以异步核验的工作从讲授时段拿出来。

内容处理方式不变的验收要求
FDE 认知、问题定义、范围和人工责任保留在课堂，用短案例触发和同伴追问完成场景机会卡、Demo Brief、范围外动作清楚
输入输出契约、材料整理和实现方式选择课堂讲原则与反例；模板填写和材料编号在节间完成字段、类型、必填、枚举、错误返回、来源和版本完整
Starter Kit 安装、环境排错和重复配置教师课前预检并提供干净副本；学员按 Runbook 完成冷启动学员能在脚手架内运行，不能把“教师机器能跑”当个人证据
T01-T12、失败注入、修订和回归课堂完成关键失败示范与复现；其余测试在节间/课后实跑12/12 实跑，有预期、实测、证据定位和版本一致性
Runbook、证据索引和演示课堂完成结构、冷启动和交叉评审；文档修订在课后完成第三方 10 分钟内启动，3 分钟内说明正常、失败、证据和边界
15 张练习卡与 24 张真实案例卡的自由探索不挤占四天主线；结课后作为换场景和延伸练习首次 L1 验收仍以固定 MVP-DEMO-01 或教师批准场景为准

四天版的硬性不减项是：10 项最终文件、9 类证据、T01-T12 12 条测试、至少一次失败驱动修订与回归、四道 L1 内部检查、第三方冷启动和 3 分钟演示。若节间证据未完成，下一节先做恢复与补证，不直接跳过。

3.5 每场课的执行合同

八节课不以“听完、安装完或成功跑通一次”作为完成。每节都按以下闭环设计，并在课末关闭本节证据：

工作任务 → 可观察能力 → 项目行为 → 必要知识 → 训练活动 → 学员交付物 → 通过条件 / 失败条件 → 来源映射

小组负责共同 Demo，个人必须能说明自己修改了什么、为什么修改、证据在哪里。仅由教师或 AI 完成而学员无法解释的改动，不计为个人能力证据。所有 Demo 版本、材料版本、测试版本和修订记录必须能够互相追踪。

4. 贯穿项目：MVP-DEMO-01 一线客服工单分诊与回复建议

4.1 场景、用户与一句话 Brief

主要用户：每天阅读产品咨询、物流、退款、账号安全和隐私请求的一线客服专员。

任务：用户粘贴一条脱敏客户消息；Demo 根据教师提供的 FAQ/政策材料，输出工单类别、优先级、材料引用、下一步建议、回复草稿和是否必须人工升级。

一句话 Demo Brief：帮助一线客服在不自动执行任何业务动作的前提下，把一条脱敏消息变成可追溯的分诊与回复建议。

4.2 教师固定材料包

教师在开课前提供脱敏、可离线使用的固定材料；所有材料版本固定为 teacher-pack-v1。学员可以整理和补充模拟材料，但不得替换安全规则或加入真实个人信息。

材料 ID建议文件内容与用途
FAQ-01materials/faq.md账号登录帮助和常见产品使用问题
POL-01materials/policies.md物流延迟超过 7 天转人工，不自动承诺赔付
POL-02materials/policies.md退款申请必须人工审核，Demo 不批准退款
POL-03materials/policies.md数据删除请求必须转隐私专员
SEC-01materials/security.md不索取密码、验证码或完整支付信息；账号风险转人工
DICT-01materials/field_dictionary.md类别、优先级、状态与错误码字典，支持契约校验
CASE-01materials/sample_messages.csv12 条脱敏样例消息，含正常、模糊和禁止行为

材料索引至少记录 material_id,version,purpose,allowed_use,prohibited_use。学员不得加入真实姓名、电话、邮箱、订单号、密码、验证码、支付信息或 API 密钥。

4.3 输入输出契约

输入示例：

{
  "request_id": "REQ-001",
  "message": "我的包裹已经超过八天没有更新，怎么办？",
  "channel": "web"
}

输入规则：

  • request_id：必填，格式 REQ-[0-9]{3}；
  • message：必填，去除首尾空白后 1-2000 字；空值或超长时不调用模型；
  • channel：必填，枚举 web | email | chat。

成功输出至少包含：

{
  "request_id": "REQ-001",
  "category": "delivery",
  "priority": "high",
  "evidence_refs": ["POL-01"],
  "recommended_action": "转人工核查物流状态",
  "draft_reply": "已记录物流延迟问题，客服将进一步核查；当前不承诺赔付结果。",
  "requires_human": true,
  "reason": "物流停滞超过 7 天",
  "status": "ok"
}

输出规则：

  • category 枚举：product_usage | delivery | refund | privacy | security | unknown；
  • priority 枚举：normal | high | urgent；
  • evidence_refs 只能包含材料索引中的 ID；无支持材料时必须为空，并将 requires_human 设为 true；
  • 退款、隐私、安全、无材料和歧义案例的 requires_human 必须为 true；
  • Schema 不合格时不得展示业务建议，统一返回 status=validation_error、error_code=OUTPUT_SCHEMA_INVALID 和 requires_human=true。

4.4 教师 Starter Kit

学员不从空白工程起步，教师提供经预检的本地或沙箱 Starter Kit：

starter-kit/
├── app/                     # 已连通的输入页、结果页和运行按钮
├── adapters/                # 教师配置的模型适配器与无付费 API 模拟器
├── config/output_schema.json
├── prompts/task_template.md # 学员允许修改的任务模板
├── materials/               # 固定脱敏材料
├── tests/test_cases.csv     # 测试模板
├── runs/                    # 每次运行的输入、输出和错误记录
├── scripts/start            # 一键启动
└── README_STARTER.md

教师必须在 S05 前完成预检：干净副本可启动；无付费 API 时仍可运行；密钥只通过环境变量注入且不写入日志；T01、T03、T06、T11 可重复；无效 Schema 和缺失材料两种故障可注入；恢复到干净副本的步骤已验证。

4.5 允许修改与禁止动作

允许修改：场景说明、任务模板、输出字段说明、枚举映射、脱敏材料、测试输入、结果展示文案、人工升级规则和运行文档。

禁止修改或执行：绕过 Schema 校验；在代码或文档中存密钥；接入真实客服/订单系统；自动发信、退款、删数或改订单；上传真实个人信息；把外部网页当作未审材料；扩大为多用户、多渠道生产服务。

4.6 正常路径与失败路径

正常路径固定为：启动并记录版本 → 输入校验 → 选择候选材料 → 调用模型或模拟器 → Schema 校验 → 规则层检查材料 ID 和人工升级要求 → 展示结果 → 保存输入、输出、错误、版本与时间。

失败路径 A：输出不符合契约。 教师注入非法 category 或删除 requires_human。Schema 校验必须阻断业务结果页并记录错误字段；学员用相同输入复现、登记失败、修改模板或规则，再重跑受影响测试，不能直接编辑输出冒充修复。

失败路径 B：材料无法支持结论。 输入询问材料包中没有的保修政策。系统不得编造政策或引用不存在的 ID，应输出 category=unknown、空 evidence_refs 和 requires_human=true。

4.8 Demo 最终通过规则

唯一测试门公式是：

12/12 executed + expected behavior matched + unresolved unexpected result = 0

负向测试出现预期的拒绝、阻断、报错或降级，属于符合预期。已经执行 12 条测试本身不等于通过；每条都必须有实际结果和证据定位，测试结果必须与最终 Demo 版本一致，失败清单不得删除，历史失败必须有关闭状态和回归证据。

第 1 天：任务与范围

L1-S01｜FDE 是做什么的：用户、任务与边界

  • 讲什么：FDE 与普通 AI 工具使用者的差别；FDE 六项能力的基本含义；Demo、Agent、Workflow 的初步区别；建议、审核和自动执行的边界；为什么“工具很强”不等于“问题值得做”。
  • 怎么设计：教师给出“公司希望全面使用 AI”的一句话。学员先写工具答案，再按“谁、做什么、现在怎么做、结果是什么、哪里不能自动做”重写。两组互相扮演客户和 FDE。
  • 90 分钟节奏：8 分钟检索“工具答案”和“任务答案”的差异；12 分钟讲 FDE 六项能力与责任边界；15 分钟示范把“全面使用 AI”收敛为一个用户和一个任务；37 分钟小组改写；12 分钟客户/FDE 角色互换走查；6 分钟关闭机会卡。
  • 本节目标：能在 60 秒内说明一个用户、一个工作任务、一个 AI 辅助点、人工责任和至少两项不适用边界。
  • 学员产出：场景机会卡 v0.1、用户任务说明、输入输出草案、风险与责任边界。
  • 通过标准：恰好一个主要用户和任务；结果可观察；至少两项范围外动作；没有敏感数据和无依据承诺。
  • 节间任务：观察一个真实岗位或选择教师岗位卡，记录一项重复、耗时或易错工作，并在 S02 前补入机会卡。

L1-S02｜把场景写成 Demo Brief

  • 讲什么：问题陈述、用户旅程、输入输出、正常路径、失败路径、成功条件、范围内/范围外、假设与依赖。
  • 怎么设计：教师把“材料整理”“生成回复”“提交审批”等动作卡打乱，学员重新排序成 5-7 步用户路径。再注入“材料缺失”和“输出不符合格式”两类失败。
  • 90 分钟节奏：8 分钟复述 S01 的用户、任务和边界；12 分钟讲 Brief、用户路径、正常/失败路径和成功条件；15 分钟示范把动作卡排序为 5-7 步流程；37 分钟完成 Brief v1；12 分钟由未参与制作的同伴冷读复述；6 分钟关闭 Brief 证据。
  • 本节目标：能把场景写成第三方可检查的 Demo Brief，而不是写一页愿景。
  • 学员产出：Demo Brief v1、5-7 步用户路径、正常路径卡、失败路径卡、验收条件。
  • 通过标准：Brief 含用户、问题、输入、输出、范围、正常和失败路径；成功条件可由输入输出判断；失败时不会自动执行高风险动作。
  • 当天任务：让一名没有参加课堂的同伴只看 Brief，复述这个 Demo 要解决什么和不解决什么；若复述不一致，当天修订 Brief v1。

第 2 天：结构化输入与材料

L1-S03｜从提示词到输入输出契约

  • 讲什么：用户输入、系统规则、上下文材料、模型输出的四层结构；提示的作用与局限；字段、类型、必填、枚举、长度、示例和错误返回；结构化输出与人工校验。
  • 怎么设计：教师展示同一个任务的自由文本结果、结构化结果和结构错误结果。学员使用模板填写 Schema，并让同伴故意输入空值、错类型和超长内容。
  • 90 分钟节奏：8 分钟检索一个字段的业务含义；12 分钟讲输入、规则、材料、输出四层结构；15 分钟对比自由文本、合格 Schema 和非法 Schema；37 分钟填写契约并制作无效样例；12 分钟同伴注入空值、错类型和超长输入；6 分钟保存契约版本。
  • 本节目标：能区分输入、规则、材料和输出；能发现结构错误字段；知道“模型输出成功”不等于“业务任务成功”。
  • 学员产出：输入输出契约 v1、有效输出、无效输出、校验错误说明。
  • 通过标准：字段、类型、必填、枚举和错误行为完整；无效结构不会显示为成功业务输出；文件中不出现密钥。
  • 节间任务：补充 3 个异常输入和预期错误返回，在 S04 前让同伴确认每个错误都能被契约或输入校验捕获。

L1-S04｜材料整理、来源追溯与实现方式选择

  • 讲什么：材料 ID、来源、版本和用途；为什么材料质量影响答案质量；Workflow、受限 Agent 和检索助手的差别；选择方式时看确定性、风险和人工确认；最小测试集设计。
  • 怎么设计：发放一批包含重复、过期、无来源和含敏感信息的材料。学员先清理和编号，再用决策矩阵选择实现方式。最后设计 T01-T12 测试。
  • 90 分钟节奏：8 分钟检索材料 ID、版本和用途；12 分钟讲材料可追溯、Workflow/受限 Agent/检索助手的选择边界；15 分钟示范清理重复、过期、无来源材料；37 分钟完成索引、决策矩阵和 T01-T12 预期；12 分钟同伴检查来源和人工确认点；6 分钟关闭材料与测试集 v1。
  • 本节目标：能判断材料是否可用、输出能否追溯、哪些步骤必须固定、哪些步骤需要人工确认。
  • 学员产出：材料包 v1、材料索引、方式选择记录、T01-T12 测试案例 v1。
  • 通过标准：材料有 ID、来源、版本和用途；实现方式符合风险；12 条测试覆盖正常、边界、异常和禁止行为。
  • 当天任务：从一条无答案问题出发，写出应当“拒答、转人工或请求补充材料”的判断，并完成至少 6 条测试的预期结果；剩余测试在 S05 前补齐。

第 3 天：运行与失败

L1-S05｜在脚手架内搭建可运行 Demo

  • 讲什么：教师脚手架目录、配置和内容边界；表单、材料检索、模型调用、Schema 校验和结果页；版本记录；启动、停止和基本日志。
  • 怎么设计：教师先用干净副本启动，再逐步拆解每个环节。学员按照任务卡完成配置，另一组只看运行说明进行冷启动。
  • 90 分钟节奏：8 分钟检索启动、版本和日志字段；12 分钟讲 Starter Kit 的入口、适配器、材料、Schema、运行记录和人工确认点；15 分钟示范干净副本启动与一次正常运行；37 分钟完成配置并跑 3 条冒烟测试；12 分钟让另一组按说明冷启动；6 分钟关闭 Demo v1 和运行证据。
  • 本节目标：能从启动到结果重复运行正常路径，知道每一步的输入、材料和输出。
  • 学员产出：Demo v1、启动与运行证据、3 条冒烟测试结果、版本标识。
  • 通过标准：干净副本可以启动；正常路径至少重复两次；结果含材料引用和人工标记；不是只有截图。
  • 节间任务：提交本人完成的一个配置或材料修改，以及对应的正常测试记录；在 S06 前补跑尚未完成的 T01-T12。

L1-S06｜测试、失败复现、最小修订与回归

  • 讲什么：正常测试、负向测试和边界测试；复现步骤；现象与根因；失败清单；最小修改；版本对比；为什么不能删除失败或修改预期迁就输出。
  • 怎么设计：教师注入无效输出、材料缺失、冲突版本和拒答失败。学员独立复现，再分组讨论是材料、规则、检索、输出校验还是流程边界的问题。
  • 90 分钟节奏：8 分钟检索“预期”和“实测”的区别；12 分钟讲失败分类、复现步骤、最小修改和回归；15 分钟示范无效 Schema 或材料缺失注入；37 分钟独立复现、登记失败、修改并重跑；12 分钟同伴审查测试证据；6 分钟关闭失败清单和修订记录。
  • 本节目标：能用固定输入复现失败，说明修改影响，并通过回归证明关键问题已关闭。
  • 学员产出：T01-T12 实测结果、失败清单、v1-v2 修订记录、Demo v2 候选。
  • 通过标准：12 条测试全部实际运行；每条都有预期、实测和证据定位；实际结果符合预先定义的行为；未关闭意外结果为 0；至少一次修订与受影响测试回归。
  • 当天任务：把一个失败写成“错误类别 + 触发条件 + 当前处理 + 后续建议”，并完成受影响测试的回归；任何未关闭意外结果必须在 S07 前标明 owner 和补做计划。

第 4 天：证据、演示与升级

L1-S07｜Runbook、证据包与 3 分钟表达

  • 讲什么：第三方复现；运行环境、输入、输出、停止、失败路径和已知限制；证据索引；如何向业务用户讲结果而不是讲模型；三分钟演示叙事。
  • 怎么设计：交换电脑或干净副本冷启动，作者只能指向文档，不能代操作。演示必须包含一次正常路径和一次失败路径，评审人按清单打分。
  • 90 分钟节奏：8 分钟检索九类证据的定位方式；12 分钟讲 Runbook、证据索引和 3 分钟业务叙事；15 分钟示范第三方冷启动与“正常-失败-边界”演示；37 分钟编写 Runbook、索引并排练；12 分钟由同伴冷启动和给出一条可执行反馈；6 分钟关闭演示版本。
  • 本节目标：让未参与制作的人在 10 分钟内复现，并让非技术用户理解价值和边界。
  • 学员产出：Runbook、完整证据索引、3 分钟演示脚本、已知限制、第三方复核表。
  • 通过标准：第三方不依赖作者口头补充；正常和失败路径可复现；九项证据可定位；演示不超过 180 秒。
  • 节间任务：根据同伴反馈修正文档，不能只修改讲稿；在 S08 前完成最终证据索引和一次完整彩排。

L1-S08｜最终运行、交叉评审与第二层申请建议

  • 讲什么：L1 内部检查；证据优先的答辩；通过、补做和暂缓；入门班与进阶班的边界；如何诚实表达“我在脚手架内完成了什么”。
  • 怎么设计：每组展示，评审人随机抽取一条正常和一条失败测试；教师追问“如果数据拿不到怎么办”“哪个动作不能自动做”“这项结果如何证明”。
  • 90 分钟节奏：8 分钟检索四道 L1 内部检查；12 分钟讲证据优先答辩、通过/补做/暂缓和进阶班边界；15 分钟教师示范随机抽测与边界追问；37 分钟小组最终运行、交叉评审和个人补证；12 分钟评审人按统一表给出结论；6 分钟提交个人复盘与升级建议。
  • 本节目标：能在 3 分钟内演示任务、运行、失败、证据和边界；能根据证据决定自己是否适合申请进阶班。
  • 学员产出：Demo v2、九项完整证据包、交叉评审表、个人复盘、第二层申请建议。
  • 通过标准：四道 L1 内部检查全部满足；T01-T12 规则满足；正常和失败路径可复现；证据版本一致；没有生产、就业或正式认证的夸大表述。
  • 结课后任务：准备进阶班申请卡并保留证据索引；默认进入 C-Bridge，申请 A-Tech 需额外完成技术诊断。结课后不得把 L1 Assisted Execution 表述为独立 L2 或生产交付能力。

  • 通过 L1 内部检查并提交完整 evidence index，可申请进阶班；
  • 默认学习轨道为 C-Bridge；
  • 有编程基础并完成额外技术诊断，才可申请 A-Tech；
  • L1 通过不等于正式 Gate 通过，不等于独立 L2 或就业资格。

7. 教师备课清单

每期开班前必须准备：

  1. 一个窄场景简报；
  2. 10-20 份公开或脱敏材料；
  3. 材料索引和版本；
  4. 教师示范版本；
  5. T01-T12 测试集；
  6. 至少 4 类失败注入；
  7. 脚手架和干净启动说明；
  8. C-Bridge 限定任务；
  9. A-Tech 可选加深任务；
  10. 评分表、交叉评审表和补做说明。

压缩班前置准备

为避免 90 分钟课堂被环境问题吞掉，教师至少在开课前 24 小时完成：

  1. 把 Starter Kit、固定材料和四天任务单发给学员；
  2. 要求学员完成一次干净副本启动、浏览 README_STARTER.md 并提交环境预检票；
  3. 收集无法启动、无权限或无法理解任务的名单，课前由助教分流；
  4. 明确第一天固定使用 MVP-DEMO-01，不在课堂临时选择新行业或接入新工具；
  5. 准备每节的缺陷版本、示范输出和同伴走查表。

S05 前还必须完成运行预检：真实模型路径和无付费 API 模拟路径各走通一次；助教用干净副本按 Runbook 复现 T01、T03、T06、T10、T11；无效 Schema 和材料缺失两类故障可注入；恢复到干净副本的步骤已验证；日志和文件中没有密钥或真实个人数据。压缩班不安排课堂现场批量安装；预检失败者先进入模拟路径，不因环境问题跳过测试和证据训练。

结课验收时，教师须核对 Demo、材料、测试和修订的版本一致性，随机复跑一条正常路径、一条关键失败路径和一条材料缺失路径，逐项检查九类证据，并单独扫描是否出现生产、就业、L2 独立能力或正式 Gate PASS 的越界表述。

教师示范必须故意保留至少一个缺陷，避免学员形成“只要照着老师做就会成功”的错觉。

8. 入门班首期测量

只记录实际发生的事实：

  • 到场人数和分组；
  • 课前预检完成率与预检失败类型；
  • 环境预检通过率；
  • 首次运行成功率；
  • 每场实际教学时间；
  • 课堂中动手、走查和测试的实际占比；
  • 助教求助次数和恢复时间；
  • 节间/课后证据任务按时提交率；
  • T01-T12 实际执行数量；
  • 失败路径复现率；
  • 第三方冷启动成功率；
  • 个人证据包完整率；
  • L1 内部检查补做率；
  • 进入进阶班后的真实完成情况。

这些数据用于优化课程，不用于未经验证地宣传学习效果、就业率或“保证达到 L2”。

9. 行业场景库与练习使用方式

9.1 场景库在入门班中的位置

行业场景库是 MVP-DEMO-01 之外的练习选择器，不改变入门班的统一交付标准。第一次练习推荐直接使用固定蓝图的一线客服场景（SC-01）；学员掌握证据链后，可从其他场景卡中选择一个岗位和一项工作，使用相同的九类证据包与 T01-T12 测试方法完成领域化 Demo。

每张场景卡都回答六个问题：谁在做什么工作、流程哪里容易出错、FDE 从哪里切入、Demo 输入输出是什么、哪些动作必须人工处理、学员如何设计测试和证据。场景卡中的“痛点”和“FDE 切口”是基于公开流程资料的教学设计推断，不是对所有组织现状的断言。

四天压缩班不要求学员在课堂内浏览完全部 15 张练习卡和 24 张真实案例卡。第一轮以固定的 MVP-DEMO-01 练习保证所有人完成同一条证据链；通过 L1 内部检查后，再用场景库做换场景练习、案例拆解或进阶班预习。这样既保留真实业务迁移能力，也避免“选题讨论”挤占 90 分钟课堂的核心训练。

9.2 学员选题流程

  1. 在门户的 行业场景库 筛选行业、难度或关键词，点击“选作练习”。
  2. 把场景卡改写成一张机会卡：只保留一个主要用户、一个工作任务和一个可观察结果。
  3. 先完成数据与责任边界，再写 Demo Brief、输入输出契约和材料索引。
  4. 为该场景准备公开、模拟或脱敏材料，设计一条正常路径、一条失败路径和 T01-T12 测试。
  5. 使用 Starter Kit 完成运行、失败复现、最小修订、回归和第三方冷启动。
  6. 最终仍须提交九类完整证据，并按 L1-G01 问题门、L1-G02 运行门、L1-G03 证据门、L1-G04 表达门验收。
