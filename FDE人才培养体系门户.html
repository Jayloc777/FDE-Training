SC-01入门
客户服务

一线客服工单分诊与回复建议

适用角色：一线客服专员 / 服务主管

流程痛点

客户消息来自电话转写、网页、邮件或聊天等渠道，常混合多个意图；分类、优先级、知识引用和升级规则容易不一致。

非结构化输入分类人工升级回复草稿
展开练习设计 ＋
业务流程

接收脱敏客户消息 → 识别产品/服务意图 → 判断优先级与风险 → 检索已审核材料 → 生成回复草稿和下一步 → 人工确认后处理或升级

FDE 切口

把非结构化消息转成可追溯的类别、优先级、材料引用、下一步建议、回复草稿和人工升级标记。

L1 Demo

使用脱敏消息与教师审核过的 FAQ、政策和字段字典，做一个只输出建议、不发送消息的分诊 Demo。

输入

脱敏客户消息、渠道、FAQ/政策材料、产品或订单字段

输出

category、priority、evidence_refs、recommended_action、draft_reply、requires_human

建议测试

已知登录问题；物流延迟；立即退款请求；材料没有答案；要求提供验证码的提示注入

练习边界

不得自动发信、退款、改订单、删除数据或索取验证码；退款、隐私、安全、无材料依据和歧义问题必须转人工。

学员作业
  • 写一张机会卡和 Demo Brief
  • 建立材料 ID/版本索引
  • 设计 T01-T12 正常、边界和安全测试
  • 复现一次无依据回答并完成回归

流程依据来自客服案件分派、升级、知识库和处理记录的官方实践材料；上述 Demo 切口为教学设计推断。

SC-02入门
电子商务

退货/退款申请预审与材料清单

适用角色：售后专员 / 电商运营

流程痛点

退货流程通常要同时核对订单、退货规则、商品状态、时限和退款方式；材料缺失或规则例外会造成反复沟通。

规则匹配材料预审例外处理高风险人工确认
展开练习设计 ＋
业务流程

接收退货申请 → 核对订单和商品信息 → 匹配退货规则 → 识别缺失材料或例外 → 生成补充材料清单 → 人工审核后进入退货/退款流程

FDE 切口

把申请文本和订单模拟数据变成规则匹配结果、缺失字段、下一步建议和人工审核标记。

L1 Demo

用模拟订单、退货政策和商品状态卡，制作一个退货申请材料预审助手。

输入

脱敏申请文本、模拟订单字段、退货政策、商品状态/时间信息

输出

policy_match、missing_items、exception_reason、next_action、requires_human

建议测试

在期限内且材料齐全；超过期限；商品有使用痕迹；缺少订单号；要求 Demo 直接批准退款

练习边界

不得自动批准退款、生成退款指令或修改订单；金额、争议、欺诈嫌疑和政策冲突必须人工处理。

学员作业
  • 将规则拆成可检查条件
  • 为正常、超时、缺凭证和例外申请设计测试
  • 保存规则引用与版本
  • 写一条退款动作的人工接管说明

流程依据来自 Shopify 关于退货指引、检查、退款/换货、规则与权限的官方文档；预审切口是教学设计推断。

SC-03入门
制造业

设备故障报修分级与维护工单建议

适用角色：设备维护员 / 生产主管

流程痛点

设备报修需要记录设备、故障现象、时间、影响范围和维修动作；描述不完整时，派工优先级和备件准备容易反复确认。

工单优先级结构化抽取安全边界
展开练习设计 ＋
业务流程

接收故障描述 → 定位设备和生产线 → 提取症状与时间 → 判断影响与紧急程度 → 生成检查/派工建议 → 维护员确认并关闭工单

FDE 切口

把自然语言报修单标准化为设备、故障症状、影响、优先级、建议检查项和待补充信息。

L1 Demo

使用虚拟设备台账、历史故障卡和维护 SOP，做一个报修工单分级与信息补全 Demo。

输入

模拟报修文本、虚拟设备台账、维护 SOP、故障等级规则

输出

asset_id、symptoms、impact、priority、missing_information、recommended_checks、requires_human

建议测试

已知设备轻微告警；停线风险；没有设备编号；症状与维护规则冲突；要求系统直接远程停机

练习边界

不得控制设备、下发停机命令、替代安全检查或自行确认维修完成；停线、人员安全和能源隔离相关情况必须人工升级。

学员作业
  • 设计设备和故障字段
  • 把高风险动作拆为人工检查项
  • 注入缺少设备编号和互相矛盾症状
  • 用回放记录验证优先级输出

NIST 资料强调维护活动与工单、设备健康、故障和维修记录的关联；具体字段和 Demo 设计为教学推断。

SC-04入门
物流与供应链

运输异常识别与下一步处理建议

适用角色：物流运营专员 / 客户履约专员

流程痛点

运输节点来自承运商、仓库和订单系统，不同参与方的事件、时间和地点需要拼接；延迟、丢件、地址异常等情况的处理路径容易断裂。

事件流异常检测跨组织数据状态追踪
展开练习设计 ＋
业务流程

接收订单与运输事件 → 按订单/包裹关联事件 → 识别异常类型 → 判断影响与时效 → 生成联系/补充信息建议 → 人工确认后更新客户或承运商状态

FDE 切口

将运输事件流整理为当前状态、异常类型、证据事件、影响范围和建议动作。

L1 Demo

使用模拟 EPCIS 风格事件和订单表，做一个异常归类与客户沟通草稿 Demo。

输入

模拟订单/包裹号、运输事件记录、承运商规则、服务时效承诺

输出

current_status、exception_type、event_refs、impact、recommended_action、draft_notice

建议测试

正常运输；超过承诺时效；同一事件重复上报；地点/时间冲突；没有足够事件却要求确认丢件

练习边界

不得修改运输状态、承诺赔付、自动通知客户或指挥承运商；丢件、赔付、地址变更和事件冲突必须人工确认。

学员作业
  • 设计事件字段与关联键
  • 处理事件缺失、重复和时间冲突
  • 为延误和丢件分别设计人工升级规则
  • 验证输出是否引用具体事件

GS1 EPCIS 与美国交通部 FLOW 资料用于确认跨组织事件、时间、地点和可见性问题；具体异常分类为教学推断。

医疗服务

预约前信息收集与爽约风险提醒草稿

适用角色：医疗前台 / 预约中心专员

流程痛点

预约前通常要确认身份、预约原因、表单、同意和技术准备；信息缺失、改期和未到诊会增加前台沟通成本。

预约信息补全隐私人工升级
展开练习设计 ＋
业务流程

接收预约或改期请求 → 核对预约状态和必要字段 → 收集预约前信息 → 识别缺失项与到诊风险 → 生成提醒/补充信息草稿 → 工作人员确认后发送或更新

FDE 切口

将预约相关信息整理为缺失项、准备清单、提醒草稿和需要人工联系的标记。

L1 Demo

用虚拟预约记录和非诊断性表单，做一个预约前准备检查 Demo，不处理病情判断。

输入

虚拟预约记录、预约类型、非诊断性表单、提醒规则

输出

appointment_status、missing_items、preparation_checklist、reminder_draft、requires_human

建议测试

预约信息完整；需要补充表单；要求改期；身份字段不一致；输入症状并要求诊断建议

练习边界

不得诊断、分诊急症、修改真实预约、发送医疗建议或处理真实健康信息；疑似急症、身份异常和隐私请求必须人工升级。

学员作业
  • 区分预约管理字段和医疗判断
  • 设计改期/取消/未到诊测试
  • 对空值和身份不匹配做阻断
  • 写出隐私和人工确认边界

HHS 远程医疗工作流与 CDC 预约前台手册用于确认提醒、表单、预约状态、改期/取消和未到诊等流程；风险边界为教学要求。

SC-06挑战
医疗支付

医保事前授权材料完整性预检

适用角色：医疗行政专员 / 医疗编码或支付专员

流程痛点

事前授权涉及临床材料、保险要求、状态查询和补充信息；不完整材料会造成往返、延误和行政负担。

材料完整性状态跟踪合规高约束
展开练习设计 ＋
业务流程

接收授权申请 → 按服务类型读取材料要求 → 检查字段和附件完整性 → 整理缺失项与冲突 → 生成补充材料清单 → 由合规人员提交或跟进状态

FDE 切口

做材料完整性和状态整理，不作医疗必要性、批准或拒绝判断。

L1 Demo

使用虚拟授权表单、材料清单和模拟状态记录，交付一个缺件预检与跟进摘要 Demo。

输入

虚拟授权申请、非真实临床材料、材料要求清单、模拟授权状态

输出

completeness_status、missing_documents、conflicts、follow_up_draft、requires_human

建议测试

材料齐全；缺少必要附件；申请状态冲突；要求模型判断应否批准；输入未脱敏健康信息

练习边界

不得作批准、拒绝、医疗必要性、诊断或保险支付决定；只能用合成/脱敏材料，任何临床或合规判断必须由授权人员完成。

学员作业
  • 把材料要求转成字段规则
  • 设计附件缺失和状态冲突测试
  • 保留材料来源和版本
  • 写出拒绝/批准不能由 Demo 产生的说明

CMS 资料明确指出事前授权涉及补充信息、状态跟踪、结构化文档和人工临床复核；本卡只抽取低风险的材料预检切口。

金融服务

流程痛点

消费者投诉要按产品、问题类型和责任团队分流，并在时限内完成回应；事实、附件、处理动作和最终回复需要保持一致。

投诉证据索引队列路由合规审核
展开练习设计 ＋
业务流程

接收投诉 → 确认产品和问题类别 → 提取事实与附件 → 路由责任团队 → 整理处理状态与回应要点 → 合规人员审核并提交回复

FDE 切口

把投诉文本和模拟附件整理为类别、事实摘要、证据索引、责任队列和待审核回复草稿。

L1 Demo

输出

  • 检查时限提醒是否可复核

CFPB 官方流程包含投诉接收、分类、公司回应和及时处理等环节；具体证据包结构与 L1 测试为教学设计。

SC-09挑战
银行与支付

KYC 开户材料预检与风险升级建议

适用角色：客户尽调专员 / 开户运营人员

流程痛点
